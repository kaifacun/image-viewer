# 시나리오 검수 — 브라우저 모드 (2026-11-19)

## 사람과 일
- **누가**: 사진 수천 장을 폴더별로 모아 둔 사용자 (맥, 트랙패드·키보드). FastStone 에 익숙함.
- **무슨 일**: "폴더를 훑어 원하는 사진을 찾아 크게 보고, 다시 목록으로 돌아와 다음 사진을 찾는다."
- **끝난 상태**: 원하는 사진이 전체 보기로 떠 있고, Esc 하면 그 사진이 격자에서 선택·보이는 상태.
- **입구**: ① `iv <폴더>` ② `iv <파일>` (Finder 에서 열기) ③ 인자 없이 (홈) ④ 트리·경로 줄로 폴더 이동.

## 실행 환경
- 실제 규모: `scratch/many` 3000장(6016px JPEG, 21GB 상당 하드링크), `scratch/fixtures` 28장(HEIC·투명 PNG·EXIF 회전 8종·12000×8000·깨진 파일·긴 한글 이름·txt), 빈 폴더(`scratch/cache`).
- 도구: 앱 자가 시험(IV_SELFTEST) — 실제 창·렌더러·egui 맞음 판정 경로. 클릭·더블클릭·휠은 egui 입력 주입, 키는 단축키 표 경유. 화면은 앱 자가 캡처로 눈으로 확인.
- 쓰지 못한 것: 실제 OS 마우스·트랙패드 이벤트(전하께서 맥을 쓰고 계심) → egui 입력 주입으로 대체. 사용자 사진 폴더는 일부러 쓰지 않음.

## 여정에서 발견해 고친 것
1. egui 0.37 `TexturesDelta` 미정리 → 디버그 빌드 즉시 abort (첫 실행).
2. 이모지 아이콘(📁 ⟳ ⛶ ⚠)이 한글 폴백 폰트에 없어 네모로 표시 → 글자로 교체.
3. 장치 손실(렌더러 교체) 뒤 새 egui 컨텍스트에서 스크롤 위치가 0으로 돌아가 선택 항목이 안 보임 → 교체 시 선택 항목으로 다시 스크롤.
4. 작은 창에서 미리보기 칸이 트리를 덮음 → 높이 60% 상한.
7. 경로 줄을 고치다 다른 곳을 누르면 고친 글자가 그대로 남음 → 확정(Enter) 아니면 현재 경로로 되돌림.
8. 교차 검증 지적: 썸네일 실패 기록이 새로고침에도 안 지워짐(영구 "열 수 없음")·누적 → 새로고침·폴더 변경 때 지움. 텍스처 상한이 보이는 썸네일보다 작으면 반복 해제 → 상한 = max(96MB, 보이는 것+32MB).
5. CPU 렌더러 UI 한 프레임 700ms (디버그 빌드 비최적화) → iv-render-cpu opt-level 3, 중앙값 12ms.
6. 썸네일 시험 기대값 오류(PNG 압축 크기 ≠ 너비 순) — 제품 결함 아님, 시험 수정.
